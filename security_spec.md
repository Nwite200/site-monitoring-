# SiteGuard AI - Security Specifications

This document outlines the security invariants, validation blueprints, adversarial payloads, and threat models for the SiteGuard AI Firestore database structure.

## 1. Data Invariants & Access Controls

SiteGuard AI uses an Express.js custom proxy architecture (`server.ts`) as the single trusted gateway for managing client website telemetry, alert logs, and Gemini AI health reports. The Express.js backend authenticates via user-supplied secrets (`ADMIN_PASSWORD`). Because the Node.js server acts as the exclusive orchestrator of the system, direct unauthenticated public access via client-side channels to Firestore must be strictly forbidden, while allowing secure read/write capabilities for authenticated operations mediated by the application credentials.

- **Websites (`/websites/{siteId}`)**:
  - A website document must contain a unique `id`, a valid `name`, a valid `url`, a `clientName`, a valid formatted `contactEmail`, and a positive `monitoringInterval`.
  - Temporal integrity: `createdAt` must be set at creation and remain immutable.
  - Value bounds: `monitoringInterval` must be a valid option (1, 2, 5, 10, 15, 30, 60).
  - State constraints: `status` must be one of `PENDING`, `ONLINE`, `OFFLINE`, `ERROR`.

- **Telemetry Logs (`/monitoring_logs/{logId}`)**:
  - Must refer to a valid `websiteId`.
  - `status` must be one of `ONLINE`, `OFFLINE`, `ERROR`.
  - `responseTime` must be a non-negative integer.
  - `checkedAt` must be a valid date-time string.

- **Alert Incident Logs (`/alerts/{alertId}`)**:
  - Must refer to a valid `websiteId`.
  - `type` must be either `DOWN` or `RECOVERY`.
  - `recipientEmail` must be a valid email format.

- **Daily Reports (`/daily_reports/{reportId}`)**:
  - Contains executive summaries generated by Google Gemini.
  - `healthScore` must be an integer between 0 and 100.
  - `uptimePercentage` must be a number between 0 and 100.

## 2. The "Dirty Dozen" Threat Payloads

The following 12 JSON payloads represent malicious or corrupted inputs trying to violate system integrity, identity, and state machine transitions.

### Payload 1: Zero-Interval Frequency Poisoning
*Target*: `/websites/site_123`
*Attack Vector*: Attempt to set `monitoringInterval` to 0 or a negative number to crash the scheduler.
```json
{
  "id": "site_123",
  "name": "Target Portal",
  "url": "https://target.com",
  "clientName": "Target Corp",
  "contactEmail": "admin@target.com",
  "monitoringInterval": 0,
  "enabled": true,
  "status": "ONLINE",
  "consecutiveFailures": 0,
  "alertSent": false,
  "createdAt": "2026-06-24T18:00:00Z"
}
```

### Payload 2: Massive Size Buffer Overflow on Email
*Target*: `/websites/site_123`
*Attack Vector*: Attempt to inject a massive 2MB string into `contactEmail` to cause a denial-of-service/wallet exhaustion.
```json
{
  "id": "site_123",
  "name": "Target Portal",
  "url": "https://target.com",
  "clientName": "Target Corp",
  "contactEmail": "A[...2000000 characters...]@target.com",
  "monitoringInterval": 5,
  "enabled": true,
  "status": "ONLINE",
  "consecutiveFailures": 0,
  "alertSent": false,
  "createdAt": "2026-06-24T18:00:00Z"
}
```

### Payload 3: Mutating Immutable Creation Timestamp
*Target*: `/websites/site_123`
*Attack Vector*: Update existing site but attempt to rewrite the `createdAt` timestamp to spoof audit trails.
```json
{
  "createdAt": "2020-01-01T00:00:00Z"
}
```

### Payload 4: Invalid Domain URL Poisoning
*Target*: `/websites/site_123`
*Attack Vector*: Attempt to create a site with invalid non-URL or malicious javascript protocols in the `url` field.
```json
{
  "id": "site_123",
  "name": "Malicious Portal",
  "url": "javascript:alert(1)",
  "clientName": "Hacker",
  "contactEmail": "hacker@test.com",
  "monitoringInterval": 5,
  "enabled": true,
  "status": "ONLINE",
  "consecutiveFailures": 0,
  "alertSent": false,
  "createdAt": "2026-06-24T18:00:00Z"
}
```

### Payload 5: Shadow Field Pollution
*Target*: `/websites/site_123`
*Attack Vector*: Create a website document with custom fields not specified in the strict schema (e.g., `isAdmin`: true) to bypass filters.
```json
{
  "id": "site_123",
  "name": "Target Portal",
  "url": "https://target.com",
  "clientName": "Target Corp",
  "contactEmail": "admin@target.com",
  "monitoringInterval": 5,
  "enabled": true,
  "status": "ONLINE",
  "consecutiveFailures": 0,
  "alertSent": false,
  "createdAt": "2026-06-24T18:00:00Z",
  "isAdmin": true
}
```

### Payload 6: Spoofing Outage Alert Type
*Target*: `/alerts/alert_123`
*Attack Vector*: Creating an alert with an unauthorized or arbitrary custom type instead of DOWN or RECOVERY.
```json
{
  "id": "alert_123",
  "websiteId": "site_123",
  "websiteName": "Target Portal",
  "url": "https://target.com",
  "type": "SUPER_CRITICAL_MALFUNCTION",
  "timestamp": "2026-06-24T18:00:00Z",
  "details": "Faking critical system alerts",
  "emailSent": true,
  "recipientEmail": "admin@target.com"
}
```

### Payload 7: Orphaned Log Injection
*Target*: `/monitoring_logs/log_123`
*Attack Vector*: Injecting logs referring to a non-existent or malicious website ID structure containing SQL injection characters.
```json
{
  "id": "log_123",
  "websiteId": "site_'; DROP TABLE websites;--",
  "websiteName": "Spoof",
  "url": "https://test.com",
  "status": "ONLINE",
  "responseTime": 120,
  "checkedAt": "2026-06-24T18:00:00Z"
}
```

### Payload 8: Fake Out-of-Bounds Gemini Health Score
*Target*: `/daily_reports/report_123`
*Attack Vector*: Creating an AI report with a `healthScore` exceeding 100 or below 0 to corrupt the analytics graphs.
```json
{
  "id": "report_123",
  "date": "2026-06-24",
  "generatedAt": "2026-06-24T18:00:00Z",
  "summary": "Corrupted report data",
  "healthScore": 9999,
  "totalChecks": 100,
  "uptimePercentage": 100,
  "slowRequestsCount": 0,
  "failuresCount": 0
}
```

### Payload 9: Invalid Latency Value Injection
*Target*: `/monitoring_logs/log_123`
*Attack Vector*: Writing negative response times to break speed analytics averages.
```json
{
  "id": "log_123",
  "websiteId": "site_123",
  "websiteName": "Target Portal",
  "url": "https://target.com",
  "status": "ONLINE",
  "responseTime": -4500,
  "checkedAt": "2026-06-24T18:00:00Z"
}
```

### Payload 10: State Machine Bypass
*Target*: `/websites/site_123`
*Attack Vector*: Bypassing intermediate statuses and forcing state changes without checking.
```json
{
  "status": "DESTROYED"
}
```

### Payload 11: Malicious ID Poisoning
*Target*: `/websites/site_$$$___$$$`
*Attack Vector*: Creating a document with special regex-breaking characters in the ID.
```json
{
  "id": "site_$$$___$$$",
  "name": "Target Portal",
  "url": "https://target.com",
  "clientName": "Target Corp",
  "contactEmail": "admin@target.com",
  "monitoringInterval": 5,
  "enabled": true,
  "status": "ONLINE",
  "consecutiveFailures": 0,
  "alertSent": false,
  "createdAt": "2026-06-24T18:00:00Z"
}
```

### Payload 12: Invalid Date Format Spoofing
*Target*: `/monitoring_logs/log_123`
*Attack Vector*: Setting `checkedAt` to a random text string instead of an ISO 8601 date-time string to crash the chronological sorting.
```json
{
  "id": "log_123",
  "websiteId": "site_123",
  "websiteName": "Target Portal",
  "url": "https://target.com",
  "status": "ONLINE",
  "responseTime": 100,
  "checkedAt": "yesterday-at-some-point"
}
```

## 3. The Test Runner Reference (`firestore.rules.test.ts`)

A mock typescript test runner implementation of how our system validates permission-denied responses for each payload.

```ts
import { assertFails, assertSucceeds, initializeTestEnvironment } from '@firebase/rules-unit-testing';

describe("SiteGuard AI Firestore Security Rules Test Suite", () => {
  let testEnv: any;

  before(async () => {
    testEnv = await initializeTestEnvironment({
      projectId: "siteguard-ai-test",
      firestore: {
        rules: "firestore.rules"
      }
    });
  });

  after(async () => {
    await testEnv.cleanup();
  });

  it("should block Payload 1 (Zero Interval Frequency)", async () => {
    const context = testEnv.unauthenticatedContext();
    const db = context.firestore();
    await assertFails(db.collection("websites").doc("site_123").set({
      id: "site_123",
      name: "Target Portal",
      url: "https://target.com",
      clientName: "Target Corp",
      contactEmail: "admin@target.com",
      monitoringInterval: 0,
      enabled: true,
      status: "ONLINE",
      consecutiveFailures: 0,
      alertSent: false,
      createdAt: "2026-06-24T18:00:00Z"
    }));
  });

  it("should block Payload 2 (Massive Size Buffer Overflow Email)", async () => {
    const context = testEnv.unauthenticatedContext();
    const db = context.firestore();
    const largeEmail = "A".repeat(10000) + "@target.com";
    await assertFails(db.collection("websites").doc("site_123").set({
      id: "site_123",
      name: "Target Portal",
      url: "https://target.com",
      clientName: "Target Corp",
      contactEmail: largeEmail,
      monitoringInterval: 5,
      enabled: true,
      status: "ONLINE",
      consecutiveFailures: 0,
      alertSent: false,
      createdAt: "2026-06-24T18:00:00Z"
    }));
  });
});
```
